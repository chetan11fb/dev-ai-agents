# ADO Story → Full-Stack Implementation Prompt

Read the Azure DevOps story through the configured ADO MCP. Extract acceptance criteria, business rules, dependencies and non-functional requirements.

Then:
1. map the story to existing domain/UI/API/data code;
2. identify gaps;
3. produce or update a specification;
4. implement .NET/C# backend and Angular/TypeScript UI using existing patterns;
5. add/update tests;
6. run accessibility/security/regression checks;
7. produce story → spec → code → tests → PR traceability.

Never invent ADO fields, credentials, APIs or domain rules.
