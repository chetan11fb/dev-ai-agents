# SDD Constitution

## Status

DRAFT — review before use.

## Principles

1. Evidence before assumption.
2. Existing architecture before new architecture.
3. Minimal coherent change.
4. API and contract safety.
5. Database and migration safety.
6. Security by default.
7. Testable behavior.
8. Observability for meaningful production behavior.
9. Accessibility for user-facing interfaces.
10. Backward compatibility unless explicitly changed.
11. Explicit human decisions for material risk.
12. No fabricated implementation evidence.

This template is intentionally technology-neutral. The Dev-AI SDD agent should adapt it to the actual repository and request human approval before treating it as authoritative.
